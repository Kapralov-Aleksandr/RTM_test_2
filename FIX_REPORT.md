# Отчёт об исправлении проблем после тестирования

## Проблема 1: start.bat закрывается, backend не связан с frontend

### Симптомы
- Start.bat закрывается сразу после запуска
- Запуск через PowerShell запускает только backend
- Frontend не стартует автоматически

### Причина
1. Неправильный путь к `venv` в команде запуска backend
2. Скрипт завершался без паузы, окна закрывались

### Решение
**Файл:** `start.bat`

**Изменения:**
1. Исправлен путь к Python: `cd backend` → `venv\Scripts\python.exe` (правильный относительный путь)
2. Добавлена пауза в конце скрипта: `pause >nul`
3. Добавлены информативные сообщения о запущенных серверах
4. Добавлена проверка существования `node_modules` с автоматической установкой

**Результат:**
- ✅ Backend запускается в свёрнутом окне на порту 8000
- ✅ Frontend запускается в видимом окне на порту 3000
- ✅ Браузер автоматически открывается на http://localhost:3000
- ✅ Скрипт не закрывается до нажатия клавиши

## Проблема 2: @-упоминания в ЧТЗ не сохраняются

### Симптомы
- При вводе `@REQ-` в ЧТЗ не появляется autocomplete
- После выбора требования бейдж не вставляется
- При сохранении упоминания не сохраняются в БД

### Причина
1. В `Editor.tsx` узел `ReqMention` не рендерил атрибуты `data-req-id` и `data-req-key`
2. Условие `selectionEmpty` вычислялось один раз при рендере и не обновлялось
3. Popup не отображался из-за устаревшего состояния

### Решение
**Файл:** `src/components/Editor.tsx`

**Изменения:**
1. Исправлен `renderHTML` для `ReqMention`:
   ```typescript
   renderHTML({ node, HTMLAttributes }) {
     return ['span', mergeAttributes(HTMLAttributes, {
       class: 'req-badge',
       'data-req-badge': '',
       'data-req-id': node.attrs.id ?? '',
       'data-req-key': node.attrs.label ?? '',
     }), node.attrs.label ?? ''];
   }
   ```

2. Убрана проверка `selectionEmpty` из условия отображения popup:
   ```typescript
   {mentionAutocomplete && sugg && suggItems.length > 0 && createPortal(...)}
   ```

3. Добавлена отладка в `refreshSuggestion`:
   ```typescript
   console.log('[Editor] @-autocomplete triggered:', { query: m[1], from, coords });
   ```

**Результат:**
- ✅ Autocomplete появляется при вводе `@REQ-`
- ✅ Бейдж вставляется с правильными атрибутами
- ✅ При сохранении упоминания извлекаются через `extractBadges`
- ✅ Список связанных требований отображается под редактором

## Проблема 3: Автоматический перенос требований из ТЗ в ЧТЗ

### Симптомы
- Если в ЧТЗ есть предложения идентичные предложениям ТЗ с требованиями, эти требования не прокидываются в ЧТЗ

### Причина
Отсутствовала логика автоматического переноса требований при совпадении текста

### Решение
**Файл:** `src/lib/autoTransfer.ts` (новый)

**Реализация:**
1. Извлечение предложений из HTML с сохранением информации о требованиях
2. Сравнение предложений из ЧТЗ с предложениями из ТЗ
3. Расчёт相似度 через сравнение слов (порог 80%)
4. Автоматическая вставка бейджей требований в ЧТЗ

**Файл:** `src/features/ChtzPage.tsx`

**Изменения:**
1. Импорт `autoTransferRequirements`
2. Вызов функции перед сохранением:
   ```typescript
   const { html: transferredHtml, transferredCount } = autoTransferRequirements(html, tzDoc);
   if (transferredCount > 0) {
     html = transferredHtml;
     editor.commands.setContent(html);
     toast(`Автоматически перенесено ${transferredCount} требований из ТЗ`, 'ok');
   }
   ```

**Результат:**
- ✅ При сохранении ЧТЗ автоматически находятся совпадающие предложения
- ✅ Требования из ТЗ прокидываются в ЧТЗ с бейджами
- ✅ Пользователь получает уведомление о количестве перенесённых требований
